## Key Design Decisions

### 1. Non-Blocking Audit Logging
- Wrapped in try-catch blocks
- Failures logged to console but don't block main operation
- Ensures business logic continues even if audit logging fails

### 2. Placement After Success
- All audit logs placed AFTER successful database operations
- Ensures we only log actions that actually completed
- No audit logs for failed operations

### 3. Action Names
- `ENTRY_CREATED` - When production entry is created
- `ENTRY_APPROVED` - When manager/admin approves pending entry
- `ENTRY_REJECTED` - When manager/admin rejects pending entry

### 4. Entity Information
- Entity Type: `'job_entry'`
- Entity ID: The UUID of the job entry

## Audit Log Data Structure

Each audit log record contains:
```typescript
{
  user_id: string | null,      // From auth.getUser()
  action: string,                // 'ENTRY_CREATED' | 'ENTRY_APPROVED' | 'ENTRY_REJECTED'
  entity_type: string,           // 'job_entry'
  entity_id: string | null,      // Job entry UUID
  metadata: any,                 // null (not used in Phase 6-3)
  created_at: timestamp          // Auto-generated by database
}
```

## Error Handling

### If Audit Logging Fails:
1. Error caught by try-catch block
2. Error logged to console: `console.error('Failed to log audit trail:', auditError)`
3. Main operation continues normally
4. User receives success response
5. No rollback of main operation

### Why Non-Blocking?
- Audit logging is important but not critical
- Should not prevent users from working
- Failures can be investigated via console logs
- Database operations (main logic) take priority

```sql
SELECT
  user_id,
  action,
  entity_type,
  entity_id,
  created_at
FROM audit_logs
WHERE entity_type = 'job_entry'
ORDER BY created_at DESC;
```

**Count Actions:**
```sql
SELECT
  action,
  COUNT(*) as count
FROM audit_logs
WHERE entity_type = 'job_entry'
GROUP BY action;
```

**View Recent Activity:**
```sql
SELECT
  al.action,
  al.entity_id,
  p.full_name as user_name,
  al.created_at
FROM audit_logs al
LEFT JOIN profiles p ON p.id = al.user_id
WHERE al.entity_type = 'job_entry'
ORDER BY al.created_at DESC
LIMIT 20;
```
